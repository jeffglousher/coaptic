## 2026-09-05

* **Update**: Core hot-path / API-surface cleanup. [`Token::from_checked`](../src/message/mod.rs) is the infallible decode construction after TKL is proven (no `expect` on the parse path). Crate-root re-exports are the happy path (`Engine` / `Memory` / decode-encode / `Endpoint` / `Progress` / `Access` / `Ids` / keyed rows / Block types / main errors). Typestate `Missing` / `Present`, raw `*Table` / `*Pool` types, and backend traits stay in `storage` / `message`. Dual `Engine::acquire_dedup` / `acquire_observe` (+ release/rotate) are `pub(crate)`; public callers use typed `insert_*` / `take_*`. Thin `#[inline]` on Engine BodySlots forwards. Builder typestate `expect` after proven gates remains. No behavior change, no new deps, no plugtest harness, no `design.md` change.
* **Update**: Q-Block missing-block recovery on the existing Incoming Body Pool / [`BlockTransfer`](../src/storage/block.rs) window bitmap. [`Engine::progress`] surfaces at most one [`QBlockRecover`](../src/storage/block.rs) per pass (rotating RX body cursor): first known hole below the highest received NUM, or at/before M=0, plus a compact in-window hole mask. Incoming Q-Block2 recover encodes repeatable Q-Block2 options (`encode_q_block2_recover_tx`). Incoming Q-Block1 stays structured work (caller owns 4.08). Outgoing reissue (`reissue_q_block1` / `reissue_q_block2`) reads the complete body without changing window state. `.block_wise(false)` stays `None` / `NoBodyPools`. No 4.08 / 2.31 / RST policy. No BERT, SZX×1–25 harness, or `design.md` change.
* **Update**: Observe notify on the existing [`ObserveInterest`](../src/storage/table.rs) row (`seq` + `pending`; no seventh area, no queued bodies). [`Engine::signal_observe`] marks due (coalesces). [`Engine::progress`] surfaces at most one pending interest per pass from the Observe cursor, assigns the next 24-bit sequence (RFC 7641 wrap), and clears pending. Caller encodes the notification with existing Observe option helpers and Access. Q-Block missing-block recovery stays a stub. No `design.md` change.
* **Update**: Bounded [`Engine::progress`](../src/storage/progress.rs) (`Progress`: at most one `poll_retransmit` plus one rotating unpinned RX datagram step per call). Caller `now_ms`; no OS clock; no send; no alloc; no storage growth. Access pins are skipped (progress does not release pinned slots). Observe notify and Q-Block missing-block recovery are documented stubs (`None`). No `design.md` change.
* **Update**: Temporary application [`Access`](../src/storage/access.rs) / `AccessMut` to occupied RX/TX datagram and body bytes. Pin bit on the occupancy word: `release` of that id is [`SlotError::Pinned`] until `Drop` unpins. Rotate is cursor-only and does not evict, so it is not blocked. Exclusive: a second pin of the same slot is `Pinned`. No alloc, no unsafe. Engine: `access_rx` / `access_tx` / `access_tx_mut` / `access_rx_body` / `access_tx_body_mut`. Not progress loop, Observe notify, or Q-Block missing-block recovery. No `design.md` change.
* **Update**: Message ID sequence (`Ids`: wrapping `u16` counter) and Token mint (`Token::mint` / `Token::mint_from` + `TokenSource`). Caller-owned, `Copy` / `no_std`. Core does not call an OS RNG (same posture as `Transmission` jitter). CON/NON request skeletons (`Message::con` / `Message::non`, `Ids::request`) take the next MID + token with no `Engine`. Token length remains 0..=8. No crate-root re-export of `Ids` / `TokenSource`. No Access, progress, Observe notify, or Q-Block recover. No `design.md` change.

## 2026-09-04

* **Update**: CON retransmission / RTO on the existing `PendingCon` TX sidecar (`PendingRto`: attempts, next-due, current timeout). Caller injects `now_ms` and `jitter_ms` (core has no OS clock or RNG; `Transmission::initial_timeout_ms` clamps jitter to the ACK_RANDOM_FACTOR span). `poll_retransmit` scans pending TX slots (O(n)); exponential backoff; `Retransmit::GiveUp` at `MAX_RETRANSMIT`. Empty ACK/RST already cleared pending and now clears RTO. `NSTART` is a per-endpoint outstanding-CON count on `record_pending_con` (message layer only; not exchange/NON). No socket send. No `design.md` change.
* **Update**: Outgoing Q-Block1 / Q-Block2 windowed send on the existing Outgoing Body Pool (`BlockTransfer` issued-window bitmap, RFC 9177 §7.2 `MAX_PAYLOADS` default 10). Issue up to 10 outstanding NUMs per window (increasing NUM). Window advances on a peer Continue NUM (Q-Block1: last of `MAX_PAYLOADS_SET`; Q-Block2: next-window base). Empty ACK is not a window ACK. Encode helpers write Q-Block + Size1/Size2. Classic Block and incoming Q-Block paths unchanged. No BERT, missing-block recovery, Request-Tag/ETag identity, or SZX×1–25 harness. No `design.md` change.

Out-of-order in-window fill, duplicate / outside-window reject, window advance, complete on M=0 with gaps filled. Classic Block paths unchanged. No BERT, Q-Block transmit, Request-Tag/ETag identity, or SZX×1–25 harness. No `design.md` change.
* **Update**: Classic Block client directions on the same `BlockTransfer` / `BodySlots` model: incoming Block2 (admit/write/apply/`apply_block2_rx`) and outgoing Block1 (start/`next_block1`/`encode_block1_tx`). Same in-order / SZX-lock / overflow rules as incoming Block1 and outgoing Block2. No Q-Block window, BERT, or SZX×1–25 harness. No `design.md` change.
