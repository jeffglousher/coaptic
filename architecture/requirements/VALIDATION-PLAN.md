# Selected-profile qualification plan

This plan tracks finite proof for the direct UDP endpoint milestone selected by
the [IETF plan](../IETF-RFC-PLAN.md). RFC ledgers own requirement applicability;
issues own remaining work. Implemented behavior, independent interoperability
and physical qualification are separate claims.

## Evidence contract

A result identifies clean core/companion commits, lockfiles, compiler, features,
runner/target, capacities and actual peer/backend. Device results also bind archive,
image, installation receipt and observed firmware. A newer CI pin or matching
feature name does not update old evidence; reuse requires matching source/boundary.

Retain original failures, unsupported directions, deadlines, capture bounds and
fresh recovery. ACK is not an application commit. Shared-backend tests do not prove
independent cryptographic interoperability, and a fixture/RFC conflict is never
relabeled literal PASS. Inventories and test totals are not whole-RFC ledgers.

Reuse compatible build lanes, disable unnecessary debug/incremental output and
assign artifacts an owner, budget and release condition. Run a coherent focused
batch once; repeat for a concrete failure. Hosted CI is advisory.

## Execution order and prerequisites

1. Cleanup and the requested full local-loopback comparison are complete at the
   named snapshots above. Fix concrete coding/integration defects before expanding
   diagnostics; additional performance work needs a concrete question or request.
2. Preserve completed Q1–Q6/Q9/Q10/Q12 proof and its source/fixture limits.
   Additional workloads, targets, absolute-peak or stability campaigns need a
   concrete implementation question or requested qualification scope.
3. Complete Q7/Q8 cold-power/interrupted persistent transitions when the exact
   physical action is available. Restore original state or explicitly fail closed;
   never regenerate identity, erase NVS/history or fabricate effects/receipts.
4. Installed three-distinct-credential backup recovery and consumed-backup refusal
   remain deferred under the operator's October21 touch-dependent qualification
   deferral. Earlier TouchAlways registration/signing and software three-role P256
   proof do not establish that installed schedule. Ordinary traffic needs no touch.
5. Reverse LAN execution awaits scoped inbound Windows permission. Keep the
   working outbound path and original credentials/state intact.

## Closure rules

Close implementation work with merged source and relevant focused proof.
Qualification stays open until the selected evidence is executed/reviewed or the
operator changes scope. Unsupported roles close with an explicit scope
disposition, never an implementation claim. Preserve retained counterexamples;
aggregate totals and hosted CI do not override them.
