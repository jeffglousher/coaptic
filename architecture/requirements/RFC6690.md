# RFC 6690 Origin Discovery Requirements

## Supported boundary

The committed profile is the built-in `Site` origin discovery response enabled
by `well_known_core()`, reached through `App` on caller-owned unicast datagram
I/O. It emits root-relative links for registered decoded UTF-8 path segments,
with application-selected entries and bounded caller-owned catalog storage.
Routes and outgoing App paths permit the root as zero segments; the existing
nonempty segment and eight-segment constructor limits remain API constraints.
Incoming zero-length Uri-Path option values remain permitted. Exact decoded
`.` and `..` values are forbidden by RFC7252 section5.10.1.

Unicast query filtering is unsupported and queries are ignored. Static borrowed
route metadata and bounded borrowed discovery parsing are implemented in
[link_format](../../src/link_format.rs); the named attribute profile covers
`rt`, `if`, `ct`, `sz` and `obs` and preserves unknown extensions. Resource
Directory roles are outside the agreed direct-UDP MVP. A caller-supplied replacement for the built-in
discovery handler has its own contract. Binding on the appropriate default port
and supplying authenticated transport/runtime policy remain explicit integration
responsibilities.

This ledger assesses the source and named direct tests checked in with it.
Exact executed source/toolchain identities and results are retained in the
reviewed implementation PR. Independent discovery interoperability and the full
applicable-requirement assessment remain open; this is not a whole-RFC compliance
claim. The parent [IETF RFC plan](../IETF-RFC-PLAN.md) assigns L3 to this named
unicast discovery/metadata profile; independent proof remains open under #200.
Implementation owner: [#519](https://github.com/jeffglousher/coaptic/issues/519).

## Remaining compliance work

- Complete the applicable clause/dependency/errata inventory and all declared
  optional attribute semantics.
- Named metadata/parser direct proof is delivered in
  [link-format tests](../../tests/link_format.rs) and
  [Site metadata tests](../../src/app/site_metadata_tests.rs): grammar,
  multiplicity, quoting, cardinal overflow, exact capacity and refusal/recovery.
  Extension-specific semantics and anchor/relative-reference resolution remain
  caller-owned; this does not establish every attribute or content codec.
- Qualify independent client discovery and exact URI-to-CoAP option identity,
  including protected modes, limits and fresh recovery. The direct round-trip
  oracle is not an independent peer implementation.
- Assess the multicast-query requirements separately when destination metadata
  and the deferred multicast role are implemented. Current unicast proof does
  not establish multicast behavior.
- Retain explicit default-port, transport security and caller-runtime evidence
  for each claimed deployed profile. Optional filtering may remain unsupported
  with its required query-ignore behavior; no broad filtering claim is made.

Normative sources: retained [RFC6690](../../knowledge/rfcs/rfc6690.txt) sections2,
2.1,4 and4.1; [RFC7252](../../knowledge/rfcs/rfc7252.txt) sections5.10.1 and6.5.
